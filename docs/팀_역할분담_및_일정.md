# 팀 역할 분담 및 일정 (9/21 ~ 9/30)

이 문서는 `3-2-Capstone_Project_Plan.md`의 "단계별 구현 순서"를 3인 팀이 실제로 어떻게 나눠서 진행할지 정리한 실행 계획입니다. 0단계(프로젝트 셋업 — Spring Boot/React 뼈대, DB 연결, 카카오맵 렌더링)는 9/21에 완료된 상태를 기준으로 합니다.

## 역할 분담 원칙

프론트엔드/백엔드/알고리즘처럼 기술 계층으로 나누지 않고, **기능 단위(화면 하나를 화면부터 저장까지 통째로)**로 나눕니다. 각자 자기 기능에서 막히는 부분(프론트든 백엔드든)은 Claude Code에게 그때그때 도움을 받아 채웁니다.

| 담당 | 맡는 기능 | 하는 일 |
|---|---|---|
| **1번 — 지도&경로** | 홈/지도 화면 | 지도 표시, 출발지·도착지 검색, 최단경로 vs 안심경로 계산 후 지도에 듀얼 표시 (가장 핵심·고난도 영역) |
| **2번 — 제보하기** | 제보 등록 | 지도 클릭 → 카테고리 선택 → 사진 첨부 → 제보 저장, 지도 위 위험구간 마커 표시 |
| **3번 — 마이페이지** | 마이페이지 | 내가 등록한 제보 목록, 즐겨찾기 등록/조회. 로그인 화면 대체용 "임시 사용자 처리"도 함께 담당 |

**로그인 화면 관련 결정**: 정식 로그인/회원가입 화면은 만들지 않고, 앱 최초 접속 시 임시 사용자(세션 기반 익명 ID)를 자동 생성해서 사용합니다. 백엔드의 `Member` 엔티티는 그대로 두고, 나중에 정식 로그인 붙일 여지를 남겨둡니다.

## 시작 전 공동 작업 (9/21, 하루 안에 끝내기)

시연 지역 보행로 교차로 좌표 20~30개를 지도에서 찾아 수동으로 입력하는 작업. 코딩 실력과 무관한 단순 반복 작업이라 3명이 나눠서(1인당 7~10개) 같이 끝냅니다. 이게 끝나야 1번 담당자가 경로 계산을 시작할 수 있습니다.

## 지켜야 할 원칙

1. **9/25 점검일을 실제로 지킬 것.** 이날 핵심 흐름(제보 → 지도 반영 → 경로 재계산)이 안 잡혀 있으면, 낙관하지 말고 그날 바로 범위를 줄이는 결정을 내립니다 (예: 마이페이지 더 단순화, 제보 카테고리 개수 축소, 히트맵을 단순 마커로 대체).
2. **9/29부터는 새 기능 추가 금지.** 리허설 중 욕심이 생기더라도, 이 시점부터는 있는 기능이 발표 때 안 터지게 하는 것이 최우선입니다.
3. 실시간(WebSocket) 반영은 고도화 항목으로, MVP에는 필요하지 않습니다. 새로고침으로 갱신되는 정도면 충분합니다.
