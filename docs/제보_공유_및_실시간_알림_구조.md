# 제보 공유 및 실시간 알림 구조 — 팀원끼리 같이 테스트하려면

> 작성: 2026-10-12. 지금은 **보류** 상태이고, 어떤 방법으로 갈지는 **팀이 이 문서를 보고 직접 선택**한다 (기획 문서 고도화 6번 "AWS DB 전환"과 연결).
> 핵심 사실: DB만 공유하면 제보 데이터는 공유되지만, 실시간 알림까지 되려면 **백엔드도 하나**여야 한다.

## 1. 지금 상황 — 왜 팀원에게 내 제보가 안 보이나

팀원마다 자기 노트북에서 백엔드(Spring Boot)와 MySQL을 따로 띄우고 있다. 즉 **서로 완전히 다른 서버 여러 개**를 쓰고 있다.

```
[내 노트북]                       [팀원 노트북]
브라우저 ─ 백엔드 ─ MySQL          브라우저 ─ 백엔드 ─ MySQL
          (내 제보만 저장)                   (팀원 제보만 저장)
```

- 제보는 등록한 사람 노트북의 DB에만 저장된다 → 팀원 지도에는 절대 안 나타남
- 실시간 알림도 각자 서버 안에서만 돈다 → 팀원에게 팝업이 가지 않음
- **버그가 아니라 서버가 다르기 때문.** 같은 서버에 접속한 사용자끼리는 정상 동작함 (2026-10-12 두 사용자 브라우저로 확인: 등록 팝업, 상대방 새 제보 팝업, 알림 배지, 새로고침 없이 마커 표시, 삭제 반영 모두 정상)
- 혼자 확인할 때는 같은 PC에서 일반 창 + 시크릿 창을 띄우면 서로 다른 사용자로 인식된다 (브라우저마다 deviceId가 다름)

## 2. 실시간 알림이 동작하는 방식

알림은 **DB가 아니라 백엔드 서버가** 보낸다.

1. 사용자가 제보 등록 → `POST /api/reports` → 백엔드가 DB에 저장
2. 저장(커밋)이 끝나면 백엔드가 WebSocket(STOMP) `/topic/reports`로 **그 백엔드에 연결된 브라우저들에게만** 새 제보를 보냄 (`ReportServiceImpl.broadcastAfterCommit`)
3. 각 브라우저(`useNotifications.jsx`)가 받아서 팝업 + 알림 목록 + 지도 마커 다시 불러오기
4. 삭제도 같은 방식: `/topic/reports/deleted`

WebSocket 메시지 중계는 Spring 내장 SimpleBroker(서버 메모리)라서, **백엔드가 여러 대면 서로의 메시지를 모른다.** 이게 "DB만 공유하면 반쪽"인 이유다.

## 3. 해결 방법 비교

| 방법 | 제보 공유 | 실시간 팝업·마커 | 다른 기기에서 현재 위치 기능 | 작업량 |
|---|---|---|---|---|
| A. 한 사람 노트북을 서버로 (같은 와이파이) | ✅ | ✅ | ❌ (HTTPS 아님) | 작음 |
| B. AWS에 **DB만** 올리고 백엔드는 각자 | ✅ (새로고침해야 보임) | ❌ | — | 중간 |
| C. AWS에 **DB + 백엔드** 같이 올리기 | ✅ | ✅ | ✅ (HTTPS 붙이면) | 큼 |
| D. 백엔드 여러 대 + 메시지 중계(Redis 등) | ✅ | ✅ | — | 큼, 지금 규모엔 과함 |

### A. 한 사람 노트북을 서버로 쓰기
한 명이 백엔드·프론트를 켜고, 나머지는 같은 와이파이에서 `http://<그 노트북 IP>:5173`으로 접속한다.
프론트 dev 서버가 `/api`, `/uploads`, `/ws-stomp`를 백엔드로 넘겨주는 구조(`front/vite.config.js`의 proxy)라 **5173 포트 하나만 열면 된다.**

필요한 준비:
- `front/vite.config.js`의 `server`에 `host: true` 추가 (또는 `npm run dev -- --host`)
- 서버 노트북 Windows 방화벽에서 5173 포트 인바운드 허용
- 카카오 개발자 콘솔 → JS 키 → 플랫폼(Web) 사이트 도메인에 `http://<IP>:5173` 추가 (안 하면 지도가 안 뜸)
- IP는 `ipconfig`의 IPv4 주소. 와이파이가 바뀌면 IP도 바뀌어 도메인 등록을 다시 해야 할 수 있음

한계:
- 브라우저는 `localhost`나 HTTPS가 아니면 위치 권한을 막는다 → **다른 기기에서는 현재 위치 표시·현재 위치 출발이 안 됨** (서버 노트북 본인만 됨)

### B. AWS에 DB만 올리기
각자 백엔드의 DB 접속 주소만 AWS(RDS 등)로 바꾸는 방식. 코드 변경은 거의 없다 (`.env`에 `spring.datasource.url` 등).

- 제보 데이터는 공유됨 → 다른 사람 제보가 지도에 **새로고침/재진입 시** 보임
- 실시간 팝업·마커는 안 됨 → 내 제보는 내 백엔드에 연결된 사람(나)에게만 알림이 감
- 즉 지금 만든 실시간 기능을 시연할 수 없음

### C. AWS에 DB + 백엔드 같이 올리기
백엔드를 EC2/Elastic Beanstalk 등 서버 한 대에 올리고, 모든 사용자가 그 서버에 접속한다.

- 모든 기능이 같은 서버를 보므로 제보 공유 + 실시간 알림 모두 동작
- 도메인 + HTTPS(예: 로드밸런서 인증서, 또는 Nginx + Let's Encrypt)를 붙이면 휴대폰 등 다른 기기에서도 현재 위치 기능 동작
- 프론트는 빌드 결과(`front/dist`)를 같은 서버나 S3/CloudFront에 올림. 이때는 Vite proxy가 없으므로 `/api`, `/ws-stomp`, `/uploads`를 백엔드로 보내는 설정(Nginx 등)이 필요
- 체크할 것: 카카오 JS 키 도메인 등록, `app.cors.allowed-origins`, 제보 사진 저장 위치(`app.upload-dir` — 서버 디스크 또는 S3), `.env` 비밀값(카카오 REST 키, DB 계정)은 서버 환경변수로만 관리

### D. 백엔드 여러 대 + 메시지 중계
STOMP SimpleBroker 대신 Redis Pub/Sub 같은 외부 중계를 붙여 여러 백엔드가 알림을 주고받게 하는 방식. 운영 서비스에서는 쓰지만 캡스톤 시연 규모에는 과하다.

## 4. 팀이 정할 것

현재 상태: **보류.** 각자 노트북에서 실시간 기능을 확인할 때는 같은 PC에서 일반 창 + 시크릿 창을 띄우면 된다.
