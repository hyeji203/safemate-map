# 프로젝트 구현 가이드 — 도와줘, 맵!

이 문서는 Claude Code가 이 프로젝트를 구현할 때 참고하는 작업 순서/우선순위 가이드입니다.
**작업 시 이 문서의 단계 순서를 반드시 지켜주세요.** 뒷 단계 기능을 먼저 만들지 말고, 앞 단계가 실제로 동작하는 것을 확인한 뒤에 다음 단계로 넘어갑니다.

## 프로젝트 한 줄 요약
공공데이터(보안등·CCTV)와 시민 실시간 제보를 결합해, 기존 '최단거리' 방식이 아닌 위험 가중치를 반영한 '가장 안전한 보행 경로'를 추천하는 반응형 웹 서비스.

## 기술 스택 (고정)
- Frontend: React
- Backend: Spring Boot
- 지도: Kakao Maps SDK
- 실시간 통신: WebSocket (STOMP + SockJS)
- DB: MySQL (AWS DB 전환은 최종 단계에서만 고려, 지금은 시도하지 않음)
- 알고리즘: Java(Spring 내부) 또는 Python — 다익스트라 변형

## 마감
9월 30일. 오늘 기준 약 2주.

## 팀 작업 방식
3인이 역할을 엄격히 나누지 않고 함께 작업. Claude Code는 특정 담당자용 코드가 아니라, 누가 봐도 이어받아 작업할 수 있는 코드/구조로 작성해주세요 (주석, 명확한 함수/파일명 중요).

"안심감"과 "경고감"을 동시에 표현하는 네이비 + 앰버 + 레드 조합.

## 전체 화면 인벤토리 (참고용 — 구현 순서는 아래 "단계별 구현 순서"를 따를 것) *(9월 팀 회의로 구조 확정, 갱신됨)*

내비게이션: 하단 탭 방식이 아니라 상단/고정 구성 — 로고(홈 이동) · 위험 제보하기 버튼(눈에 띄게) · 마이페이지 · 서비스 소개(선택)

| 우선순위 | 화면 |
|---|---|
| 필수 (MVP) | 홈/지도 화면 (지도 + 출발지·도착지 검색 + 최단/안심 경로 듀얼 표시 + 실시간 제보 마커·히트맵 오버레이) |
| 필수 (MVP) | 제보 등록 (지도 클릭 시 카테고리 선택 + 사진 첨부 모달) |
| 필수 (MVP) | 마이페이지 (내 제보 목록 + 즐겨찾기 — 즐겨찾기는 독립 화면 아님) |
| 고도화 | 서비스 소개/이용안내 (나머지 필수 기능 다 끝난 뒤 시간 남으면) |

> 기존 "즐겨찾기·알림 독립 탭 + 로그인 화면" 4탭 구조는 팀 논의로 위와 같이 단순화됨. 지도 화면 + 제보 등록 두 가지만 확실히 동작해도 시연 임팩트는 충분하다는 판단.
> "제보 알림/히트맵"은 네비게이션에 별도 진입 경로가 없어 독립 화면이 아니라 홈/지도 화면 위에 얹히는 오버레이 기능으로 정리함 (위 표에 반영).
> **확인 필요**: 로그인/회원가입 화면이 새 구조에는 명시되어 있지 않음. 제보자 식별·중복 제보 방지가 필요한지, 필요하면 어떤 방식으로 처리할지 팀과 재논의할 것. 확정 전까지는 익명 제보 허용 등 최소 기능으로 가정하고 진행해도 무방.

## 우선순위 원칙 (가장 중요)

1. **동작하는 것 > 완벽한 것.** 매 단계마다 "일단 끝까지 눈으로 확인 가능한 상태"를 먼저 만들고, 그다음 다듬는다.
2. **고도화 기능은 핵심 기능이 끝나기 전까지 절대 먼저 만들지 않는다.** (아래 "고도화 기능" 섹션은 2단계까지 핵심 흐름이 다 돌아간 뒤에만 착수)
3. 막히면 범위를 줄여서라도 "제보 → 지도 반영 → 경로 재계산"이라는 핵심 흐름 하나는 반드시 끝까지 연결되게 한다.

## 단계별 구현 순서

### 0단계 — 프로젝트 셋업
- [ ] Spring Boot 프로젝트 초기 생성 (REST API 서버 구조)
- [ ] React 프로젝트 초기 생성
- [ ] MySQL 연결 확인 (더미 데이터로 CRUD 테스트)
- [ ] Kakao API 키 발급 및 분리 적용
  - JavaScript 키 → React(프론트엔드), 지도 렌더링용
  - REST API 키 → Spring Boot(백엔드), 주소 검색/좌표 변환용
  - 두 키 모두 `.env`로 분리 관리 (Git에는 올리지 않음). `application.yml`에는 `${KAKAO_REST_API_KEY}` 형태로 환경변수 참조만 작성
  - Spring Boot에서 `.env`를 인식시키려면 `spring-dotenv` 의존성 추가 또는 `.vscode/launch.json`의 `envFile` 설정 필요
  - React `.env`는 변수명 앞에 `REACT_APP_` 접두사 필요 (예: `REACT_APP_KAKAO_JAVASCRIPT_API_KEY`)
- [ ] 카카오맵 API 키로 지도 하나 화면에 띄우기 (React 쪽)
- [ ] GitHub 레포 구조 잡기 (`main` / `develop` / `feature/*` 브랜치 전략)
  - `.gitignore`에 `.env` 추가. 이미 커밋된 민감 파일이 있다면 `git rm --cached`로 제거 필요

> 목표: "지도가 화면에 뜬다" + "DB에 더미 데이터 CRUD가 된다"는 두 가지가 각각 눈으로 확인되면 0단계 완료.

### 1단계 — 데이터 모델 & 기본 그래프
- [ ] DB 테이블 설계 및 생성: 제보(reports), 보행로 노드(nodes), 간선(edges) 등
- [ ] 시연 지역의 보행로 교차로(20~30개 예상)를 노드/간선 데이터로 수동 입력 (좌표, 거리)
- [ ] 이 그래프 데이터로 **가중치 없는 기본 최단경로(다익스트라)** 가 동작하는지 확인

> 목표: 출발지/목적지를 주면 "최단경로"가 최소한 콘솔/API 응답으로 나오는 상태.

### 2단계 — 핵심 기능 (제보 → 경로 반영)
- [ ] 제보 등록 REST API (`POST /reports`): 위치, 카테고리(가로등 고장/어두움/인적 드묾), 시각 저장
- [ ] 제보 조회 API + React 지도 위 마커 표시
- [ ] 제보 등록 폼 UI (지도 클릭 → 카테고리 선택 → 등록)
- [ ] 제보 데이터를 간선 가중치에 반영하는 로직 추가 (제보 밀도가 높은 구간일수록 가중치 ↑)
- [ ] **"최단경로" vs "안심경로"를 동시에 계산해서 React 지도에 두 경로 같이 표시**
- [ ] 마이페이지 기본 구현: 내가 등록한 제보 목록 조회 + 즐겨찾기 장소/경로 등록·조회 (별도 화면이 아닌 마이페이지 하위 기능, 단순한 형태로도 충분)

> 이 단계가 프로젝트의 핵심입니다. 이게 끝까지 동작하면 사실상 MVP는 완성입니다.
> 목표: 제보를 하나 등록했을 때, 그 근처를 지나는 안심경로가 최단경로와 달라지는 게 눈으로 보이면 2단계 완료.

### 3단계 — 다듬기 (마감 직전 필수 항목만)
- [ ] UI 반응형 확인 (모바일/PC 뷰포트)
- [ ] 에러 처리 (API 실패, 빈 경로 등 엣지 케이스)
- [ ] 발표/시연용 더미 제보 데이터 미리 세팅 (실제 시연 시 빈 화면 방지)
- [ ] 마지막 1~2일은 새 기능 추가 금지, 버그 픽스 + 리허설 전용

## 고도화 기능 (2단계 완료 후, 시간 남으면 순서대로 시도)

**중요: 아래는 2단계가 완전히 동작을 확인한 뒤에만 시작합니다. 순서도 이대로 지켜주세요.**

> 진행 상태: ✅ 완료 / ⬜ 남음 / ❌ 하지 않기로 함 (2026-10-12 기준)

1. ✅ **실시간 반영 (WebSocket/STOMP)**: 제보 등록 시 다른 사용자 화면에도 실시간으로 반영. 안 되면 새로고침 기반으로도 시연 가능하므로 최우선 순위 아님.
   - 완료: 새 제보 알림·팝업(#22~#24, #26), 제보 삭제 반영, 지도 마커 실시간 갱신(#26)
2. ⬜ **시간 감쇄 로직**: 오래된 제보일수록 가중치 영향력 감소하는 함수 적용. → 아래 "고도화 후보 상세" 2번
3. ⬜ **카테고리별 차등 가중치**: 가로등 고장(객관적 위험)과 인적 드묾(주관적 체감)의 기본 가중치·감쇄 속도를 다르게 설계. → 아래 "고도화 후보 상세" 2번
4. ❌ **제보 신뢰도 검증**: 동일 사용자 중복 제보 필터링, 신뢰도 점수화 (어뷰징 방지).
   - 점수화는 팀 결정으로 하지 않음. 어뷰징 대응은 아래 "고도화 후보 상세" 9번(부적절한 제보 신고)으로 대신함
5. ✅ **OSM 기반 도로망 자동 확장**: 수동 입력 대신 OpenStreetMap 데이터로 그래프 자동 생성 (시연 구역 확장용, 시간 매우 부족하면 스킵).
6. ⬜ **AWS DB 전환**: 정말 시간이 남을 때만 시도. MVP 완성 전에는 손대지 않음.
7. ✅ **서비스 소개/이용안내 페이지**: 처음 온 사용자에게 서비스 설명. 마이페이지·지도·제보 등 필수 화면이 다 끝난 뒤 마지막에 추가.
   - 완료: 움짤로 보여 주는 사용가이드 튜토리얼(#19), 마이페이지에서 다시 보기
8. ✅ **제보 카테고리 확장**: 현재 3종(가로등 고장/어두움/인적 드묾) 외에 "인도 파손"(1.2 문제의식에 이미 언급됐던 항목), "CCTV 사각지대" 등 기존 컨셉(지속적 환경 위험)과 맞는 카테고리부터 추가 검토.
   - **지진 등 자연재해/사고 신고는 이 확장에서 제외하고 별도 검토 대상으로 둠.** 경로 가중치에 누적되는 지속적 위험과 달리 즉시 전체 알림이 필요한 성격이라 지금 제보 구조로 처리 불가하고, 이미 국가 긴급재난문자 체계가 지진을 다루고 있어 시민 제보 기반으로 다루는 게 얼마나 가치 있을지도 불확실함. 프로젝트 정체성("정부 데이터가 못 잡는 체감 위험")과도 다소 어긋남.

## 고도화 후보 상세 (2026-10-11 추가)

위 목록 중 1(실시간 반영), 5(OSM 도로망), 7(이용안내 튜토리얼), 8(카테고리 확장)은 구현됨(✅). 아래는 남은 항목과 새로 나온 후보를 **어떻게 구성하고 어떻게 동작해야 하는지**까지 정리한 것. 아직 구현된 항목은 없음(⬜). 하나씩 끝날 때마다 ✅로 바꾼다. 번호는 추천 우선순위(쉽고 효과 큰 것부터).

**공통 원칙**
- 사용자 현재 위치는 화면 표시에만 쓰고 서버·DB·localStorage에 저장하거나 전송하지 않는다. 아래 어떤 기능도 이 원칙을 깨면 안 된다.
- 경로 가중치를 바꾸는 기능(2번, 8번, 7번의 선택 항목)은 `RiskWeightCalculator` 한 곳에서만 계산을 바꾸고, 결과가 기존 `EdgeRisk`(어두움 0~1 + 제보 위험 0~1) 형태를 그대로 유지하게 한다. 그래야 경로 계산(`RouteServiceImpl`)·응답 형식·프론트를 건드리지 않는다.
- 제보 신뢰도 **점수**는 팀 결정으로 만들지 않는다 (위 4번 중 점수화 제외). 마이페이지의 고정값 "신뢰도 95점" 카드는 지운다. (⬜ 아직 남아 있음)

### ⬜ 1. 경로 비교 설명 문구 — 난이도 하, 프론트만
- **구성**: `MapPage.jsx`의 안심/최단 경로 카드에 한 줄 설명 추가. 서버 응답(`RoutesResponse`)에 이미 있는 `totalDistanceMeters`, `estimatedMinutes`, `darkDistanceMeters`, `reportedDistanceMeters`만 사용.
- **동작**
  - 안심경로 카드: "최단경로보다 {분 차이}분 더 걸리지만 어두운 구간이 {m 차이}m 줄어요" (제보 구간도 줄었으면 "제보 구간 {m}m 회피" 추가)
  - 두 경로가 같으면(차이 0) "이 구간은 최단경로가 가장 안전해요"
  - 안심경로가 더 짧거나 같은 시간이면 "더 걸리지만" 대신 "시간 차이 없이"
- **완료 기준**: 제보를 등록해 안심경로가 달라졌을 때 문구의 숫자가 두 카드의 값 차이와 일치.

### ⬜ 2. 제보 시간 감쇄 + 카테고리별 가중치 (위 2·3번) — 난이도 하, 백엔드만
- **구성**: `RiskWeightCalculator`에서 제보를 1건=1로 세던 부분(`r -> 1`)을 "제보 1건의 무게(0~1)"로 바꾼다. 무게 계산은 새 클래스 `ReportWeight`로 분리하고 카테고리별 값은 `ReportCategory` 옆에 상수로 둔다.
- **동작**
  - 제보 무게 = 카테고리 기본 무게 × 0.5^(경과일 / 카테고리 반감기)
  - 초안 값 (시연 후 조정):

    | 카테고리 | 기본 무게 | 반감기 | 이유 |
    |---|---|---|---|
    | 가로등 고장 | 1.0 | 30일 | 객관적 위험, 고쳐지기 전까지 오래 유효 |
    | 인도 파손 | 0.8 | 60일 | 물리적 위험, 보수가 느림 |
    | CCTV 사각지대 | 0.7 | 90일 | 거의 안 바뀌는 환경 |
    | 어두운 골목 | 0.7 | 30일 | 반 주관적 |
    | 인적 드묾 | 0.5 | 14일 | 주관적 체감, 시간·요일에 따라 바뀜 |
  - 간선 제보 위험 = min(1, 반경 25m 안 제보 무게 합 / 2) — 기존 "2건 이상이면 1" 규칙을 무게 합으로 바꾼 것
  - 무게가 0.05 미만이 된 제보는 계산에서 뺀다 (지도에는 계속 표시)
- **완료 기준**: 같은 위치에 오늘 제보 1건 vs 60일 전 제보 1건을 넣었을 때 안심경로 회피 정도가 달라짐. `createdAt`을 과거로 바꾼 더미 데이터로 확인.

### ⬜ 3. 제보 "해결됨" 처리 — 난이도 중
- **구성**
  - DB: `Report`에 `resolvedAt`(nullable) 추가 + 새 테이블 `report_resolve_vote`(report_id, member_id, created_at, (report_id, member_id) 유니크)
  - API: `POST /api/reports/{id}/resolve` (deviceId 파라미터, 기존 회원 식별 방식 그대로)
  - 프론트: `ReportDetail.jsx`에 "해결됐어요" 버튼
- **동작**
  - 제보자 본인이 누르면 바로 해결 처리
  - 다른 사용자는 1인 1표, 서로 다른 2명이 누르면 해결 처리
  - 해결된 제보는 경로 계산에서 빠지고(`RiskWeightCalculator`에 넘기기 전에 필터), 지도 마커는 회색으로 7일 동안 보였다가 사라짐
  - 해결 시 `/topic/reports/deleted`와 같은 방식으로 `/topic/reports/resolved` 브로드캐스트 → 다른 사용자 지도 갱신, 알림 목록에서 "해결됨" 표시
- **완료 기준**: 제보 때문에 돌아가던 안심경로가 해결 처리 후 최단경로와 같아짐.

### ⬜ 4. 제보 히트맵 — 난이도 중, 화면 인벤토리상 MVP 항목
- **구성**: 새 API `GET /api/reports/heatmap` → 격자 칸별 `{ lat, lng, weight }` 목록. 프론트 `KakaoMap.jsx`에 "히트맵" 토글 버튼, 카카오맵 위에 반투명 원(`kakao.maps.Circle`)으로 그림.
- **동작**
  - 칸 크기 약 50m, weight는 2번의 제보 무게 합 (2번 전이면 건수)
  - 색은 디자인 팔레트의 레드 하나로 투명도만 다르게 (weight 높을수록 진하게)
  - 토글 켜면 개별 제보 마커는 숨김, 많이 축소(레벨 6 이상)했을 때 기본으로 켜짐
  - 새 제보·삭제 브로드캐스트를 받으면 다시 불러옴 (`reportVersion` 사용)
- **완료 기준**: 제보가 몰린 곳이 진하게 보이고, 제보 추가 시 새로고침 없이 바뀜.

### ⬜ 5. 지자체 전달용 제보 모아 보기 — 난이도 중
- **구성**: 새 화면 `/stats` (마이페이지에서 진입), 새 API `GET /api/reports/stats`
- **동작**
  - 카테고리별 제보 수 (막대 그래프)
  - 동(행정동)별 제보 수 — 제보의 `address`에서 동 이름 추출
  - "가로등 고장" 제보가 많은 위치 TOP 10 (같은 25m 안 제보를 묶어서), 누르면 지도에서 그 위치 표시
  - "CSV 내려받기" 버튼 (구청 전달용 시나리오, 주소·카테고리·건수·최근 제보일)
  - 개인 정보(제보자, 사진)는 통계에 넣지 않는다
- **완료 기준**: 발표에서 "이 데이터를 구청에 넘길 수 있다"를 화면으로 보여줄 수 있음.

### ⬜ 6. 경로 위 위험 구간 강조 — 난이도 중
- **구성**: 서버 `RouteResponse`에 `segments: [{ fromIndex, toIndex, kind }]` 추가 (kind: `DARK` | `REPORTED`). `geometry`의 인덱스 범위로 위험 구간을 알려준다. 프론트는 해당 구간만 다른 스타일 폴리라인으로 위에 덧그림.
- **동작**
  - 어두운 구간(어두움 0.5 이상): 점선
  - 제보 구간: 레드 실선
  - 고른 경로(안심/최단) 카드에 맞춰 그 경로의 위험 구간만 표시
  - 위험 구간을 누르면 "어두운 구간 120m" / "제보 2건 (가로등 고장)" 말풍선
- **완료 기준**: 최단경로에는 빨간 구간이 있고 안심경로는 그 구간을 피해 가는 게 눈으로 보임.

### ⬜ 7. 경로 주변 안전시설 표시 — 난이도 중
- **구성**: 새 API `GET /api/places/safety?minLat&minLng&maxLat&maxLng` — 서버가 카카오 카테고리 검색(편의점 `CS2`, 공공기관 `PO3` 중 지구대·파출소)을 호출하고 결과를 10분 캐시. 프론트는 경로가 표시되면 경로 주변 범위로 요청해 작은 아이콘 마커 표시.
- **동작**
  - 경로선에서 50m 안의 시설만 표시
  - 편의점 🏪, 지구대·파출소 🚓 아이콘, 누르면 이름·거리
  - (선택) 안심 비용 계산 시 편의점이 가까운 간선의 위험도를 조금 낮춤 — 넣으면 2번과 같이 `RiskWeightCalculator`에서 처리
- **완료 기준**: 안심경로 위에 들를 수 있는 곳이 표시됨. API 키는 서버에만 있고 프론트로 나가지 않음.

### ⬜ 8. 시간대(낮/밤) 반영 — 난이도 하
- **구성**: `GET /api/routes`에 선택 파라미터 `time=day|night` (없으면 서버 현재 시각으로 판단). `RiskWeightCalculator`에서 어두움 값에 시간대 배율 적용. 프론트 경로 카드 위에 "낮/밤" 토글 (시연용으로 강제 전환 가능).
- **동작**
  - 밤(일몰~일출, 초안: 18시~06시): 어두움 그대로
  - 낮: 어두움 × 0.2 (가로등 유무가 거의 영향 없음), 제보 위험은 그대로
- **완료 기준**: 같은 출발·도착에서 낮/밤 토글에 따라 안심경로가 달라지는 구간이 있음.

### ⬜ 9. 부적절한 제보 신고 — 난이도 중
- **구성**: 새 테이블 `report_flag`(report_id, member_id, reason, created_at, (report_id, member_id) 유니크), API `POST /api/reports/{id}/flag`, `ReportDetail.jsx`에 "신고" 버튼.
- **동작**
  - 사유 선택: 장난 제보 / 위치가 틀림 / 부적절한 사진
  - 서로 다른 3명이 신고하면 숨김 처리 — 지도·알림·경로 계산 모두에서 제외 (삭제가 아니라 숨김, DB엔 남김)
  - 본인 제보는 신고 불가, 같은 사람 중복 신고 불가
  - 점수화는 하지 않는다
- **완료 기준**: 3개 브라우저(다른 deviceId)로 신고하면 마커가 사라지고 안심경로도 원래대로 돌아옴.

### ⬜ 10. 경로 공유하기 — 난이도 중
- **구성**: 프론트만으로 가능. 경로 카드에 "공유" 버튼 → `/?from=lat,lng,이름&to=lat,lng,이름` 형태 링크 생성, 휴대폰은 Web Share API, PC는 링크 복사. `MapPage`가 이 쿼리를 읽어 출발·도착을 채우고 경로 탐색.
- **동작**
  - 공유되는 건 **출발지·도착지(검색하거나 지도에서 고른 장소)뿐**. 실시간 위치 추적·공유는 하지 않는다
  - 출발지가 "현재 위치"인 경로는 공유 버튼을 비활성화하고 "현재 위치는 공유할 수 없어요" 안내 (공통 원칙)
- **완료 기준**: 링크를 다른 브라우저에서 열면 같은 출발·도착으로 경로가 바로 그려짐.

### ⬜ 11. 홈 화면에 앱처럼 설치 (PWA) — 난이도 하
- **구성**: `front/public/manifest.webmanifest`(이름 "도와줘, 맵!", 팔레트 네이비/앰버, 아이콘 192·512px) + `index.html`에 manifest 링크 + 최소 서비스워커(정적 파일 캐시만, API는 캐시하지 않음).
- **동작**: 휴대폰 브라우저 "홈 화면에 추가" → 주소창 없는 전체 화면으로 실행.
- **완료 기준**: 시연 휴대폰 홈 화면 아이콘으로 실행됨. (HTTPS 또는 localhost에서만 동작하므로 시연 환경 확인 필요)

### 하지 않기로 한 것
- **제보 신뢰도 점수**: 팀 결정으로 제외.
- **실시간 길 안내(턴바이턴, 위험 구간 접근 알림)**: 실제로 걸으며 테스트해야 하고 작업량이 커서 남은 기간에 맞지 않음.

### 마감 전 필수 (기능 아님, 3단계 항목)
- 시연용 더미 제보 세팅: 시연 경로 주변에 카테고리·날짜가 다양한 제보를 미리 넣어 둔다 (2번 시간 감쇄를 보여주려면 `createdAt`이 과거인 제보도 필요). 시연 당일 DB가 비어 있으면 안심경로와 최단경로가 똑같이 나온다.
- 각자 PC의 로컬 MySQL을 쓰므로 팀원끼리 제보가 공유되지 않는다. 시연은 한 PC의 서버 하나로 하고, 휴대폰 등 다른 기기는 그 서버에 접속하는 방식으로 준비.

## 시연 범위 제약 (일부러 좁게 잡은 것)
- 시연 지역: 1~2개 동 (카카오맵에서 검색·표시되는 범위 내로 한정)
- 보행로 교차로: 20~30개 수준
- 추천 경로 개수: 최대 3개

이 제약은 "구현이 부족해서"가 아니라 **의도적으로 범위를 좁혀 알고리즘/데이터 파이프라인을 빠르게 검증하기 위함**입니다. Claude Code가 임의로 범위를 넓히거나 일반화하려 하지 말고, 이 좁은 범위 안에서 확실히 동작하는 것을 우선해주세요.
